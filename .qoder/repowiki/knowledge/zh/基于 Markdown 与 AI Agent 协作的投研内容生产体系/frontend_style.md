## 1. 系统概述
本项目（AI Berkshire）是一个**纯后端/CLI 驱动的价值投资研究框架**，不包含传统意义上的 Web 前端应用、CSS 样式表或 UI 组件库。其“前端表现层”完全由 **Markdown (.md)** 文档构成，通过标准化的排版规范、Mermaid 图表和结构化表格来呈现深度投研报告。

视觉一致性不依赖于 CSS 框架，而是通过 **Skill 定义文件**（如 `skills/deep-company-series.md`、`skills/wechat-article.md`）中强制规定的**写作风格、排版结构和事实核查标准**来实现。这是一种“内容即界面”（Content-as-UI）的设计哲学，旨在确保在不同阅读器（GitHub、微信公众号、本地编辑器）中保持一致的专业感和可读性。

## 2. 核心架构与约定

### 2.1 内容载体：标准化 Markdown
所有产出物均为 `.md` 文件，遵循以下视觉与结构约定：
- **标题层级**：严格使用 `#` 到 `###` 构建文档骨架，确保大纲清晰。
- **数据可视化**：
  - **表格**：用于财务数据对比、估值指标、Checklist 评分（如 `| 维度 | 评分 | 结论 |`）。
  - **Mermaid 图表**：在 `assets/architecture.mmd` 及报告中用于绘制业务流程图、竞争格局图。
  - **图片引用**：统一存放在 `assets/` 目录，通过相对路径引用（如 `![描述](../../assets/fig1.png)`）。
- **强调规范**：
  - **加粗**：仅用于关键结论或数据，禁止密集加粗以避免“AI 味”。
  - **引用块**：用于展示大师语录（巴菲特、芒格等）或核心结论摘要。
  - **列表**：大量使用无序列表 `-` 和有序列表 `1.` 拆解逻辑链条。

### 2.2 视觉风格指南（Writing Style Guide）
在 `skills/deep-company-series.md` 和 `skills/wechat-article.md` 中定义了严格的“视觉”与“语气”规范：
- **禁用词与表达**：禁止使用“显然”、“必然”、“我认为”等主观词汇；禁止使用 emoji（除非特定场景）；禁止流量党比喻（如“YYDS”）。
- **段落控制**：公众号文章要求段落不超过 4 行，句子不超过 30 字，以适应移动端阅读。
- **公式渲染**：所有数学公式必须使用 LaTeX 格式（`$...$` 或 `$$...$$`），禁止纯文本公式。
- **配色与主题**：无自定义配色，依赖阅读器默认主题（通常为白底黑字或深色模式适配）。

### 2.3 多智能体协作流程中的“编辑”角色
在 `skills/earnings-team.md` 和 `skills/wechat-article.md` 中，引入了 **Editor Agent** 和 **Reader Agent**：
- **Editor Agent**：负责“润色结构和表达”，确保文章节奏感、标题吸引力及排版友好性。
- **Reader Agent**：从普通投资者视角审读，反馈“看不懂”或“想跳过”的部分，间接优化内容的可读性布局。

## 3. 关键文件与目录

| 文件/目录 | 作用 | 说明 |
| :--- | :--- | :--- |
| `skills/*.md` | **样式与结构定义源** | 定义了报告的模板、标题格式、表格结构和写作红线 |
| `reports/` | **内容输出库** | 存储所有生成的 Markdown 报告，按公司/行业分类 |
| `assets/` | **静态资源库** | 存储架构图 (`.mmd`, `.png`) 和数据图表 |
| `tools/report_audit.py` | **格式与数据抽检工具** | 自动提取报告中的数据点进行交叉验证，确保“视觉呈现”的数据真实性 |
| `CLAUDE.md` | **全局项目指令** | 规定了报告命名规范、目录结构和语言风格（中文、直接、犀利） |

## 4. 开发者/研究者遵循规则

1. **结构优先**：新报告必须遵循 `skills/investment-team.md` 或 `skills/deep-company-series.md` 中定义的章节结构（如“一句话结论”、“四维评分总表”）。
2. **数据表格化**：关键财务数据、估值对比、风险清单必须使用 Markdown 表格呈现，严禁大段文字罗列数字。
3. **来源标注**：所有数据必须在表格下方或脚注中标注来源（如 `Sources: SEC 6-K, MacroTrends`）。
4. **图片处理**：
   - 论文解读类文章必须从 PDF 提取高清原图（≥500KB），禁止使用占位符。
   - 图片统一存放在 `assets/{主题}/` 目录下。
5. **禁止硬编码样式**：不使用 HTML 标签进行样式控制（如 `<font color=...>`），保持 Markdown 的纯净性，依赖阅读器渲染。
6. **一致性检查**：在系列报告中，跨篇目的数字（市值、持股比例）和术语口径必须保持一致，通过 `Explore agent` 进行扫描。

## 5. 总结
AI Berkshire 的“前端风格”是**高度结构化、数据驱动且去装饰化**的。它放弃了传统的 CSS 美学，转而追求**信息密度、逻辑清晰度和数据可信度**的极致表达。其视觉一致性通过严格的 Markdown 模板和 AI Agent 的编辑评审流程来保障，适用于专业投研场景下的高效阅读与决策支持。
