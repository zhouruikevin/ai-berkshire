## 怎么用(导师协议)

每个主题走一遍"上课循环":

1. **开课** — 导师(我)贴出该主题话题卡。你带着"驱动问题"去读材料清单里的源码。
2. **回课** — 你回来触发考问:说「考我 T1」,或直接开始答驱动问题。
3. **考问** — 我出 3-5 题,每题前标开/闭卷:
   - `[闭卷]` **概念题**(为什么这样设计):不可查资料/源码,考"是否内化"。中途去翻请如实说,我按"提示后答对"降档(满★→★4)。
   - `[开卷]` **源码定位题**(某逻辑在哪 / 怎么实现):鼓励翻源码,考"知道去哪找"。
   - **动手任务**:全程开卷。
4. **评分** — 我对照源码判对错、指出盲点,给该主题 **★1-5 掌握度**。**★≥4 解锁**下一主题;<4 我指定"回炉"材料段落重学。
5. **记录** — 我就地更新下方进度表。

> 跨会话:进度写在本文件里。新开对话时说「继续学习系统」,我读本文件头即可续上。

## T1 · Skill 即 Prompt 工程(母版)

- **🎯 学习目标**:讲清一份 Markdown(`skills/*.md`)是怎么变成一套可执行、可复现的研究流程的——为什么用"强制步骤 + 工具调用"而不是让 AI 自由发挥。
- **🔌 工程师类比**:Skill ≈ **声明式 DSL / 配置文件**(像 Flutter widget 声明式描述 UI,你写"要什么",执行层负责"怎么做");占位符 ≈ **模板变量**(但注意:`$ARGUMENTS` 与 `$CURRENT_DATE` 是两套不同机制,见下方延伸笔记)。
- **❓ 驱动问题**:
  1. frontmatter 里**必须**有哪两个字段?各自作用是什么?
  2. `$ARGUMENTS` 和 `$CURRENT_DATE` 分别在什么时候、被什么替换?
  3. 七模块研究框架按顺序是哪七个?每个模块挂在哪位大师名下?
  4. "AI 研究偏见自觉"的 A/B/C 级分别指什么?为什么信息越充裕(A 级)反而 alpha 越少?
  5. 为什么要在 Skill 里**强制嵌入工具调用**(如 financial_rigor.py),而不是信任 AI 自己算?
- **📂 材料清单**:`skills/investment-research.md` 全文(276 行)。延伸:现有计划 阶段三 3.1。
- **🛠️ 动手任务**:在白纸/白板上画出 investment-research 的执行流程图(偏见自觉 → 数据收集 → 七模块 → 工具验证 → 报告准出)。

- **📌 延伸笔记(2026-07-24 考问中挖出,依据 Claude Code 官方 slash-commands 文档)**:
  - **harness(加载层)= 平台运行时**(Claude Code / Qoder / Codex),包在**无状态**大模型外:负责拼上下文、注入环境信息、执行工具、跑 agent loop。是 agent 圈通用概念,**非 Claude Code 独有**;直接调 API 时 harness 就是你自己的代码。模型不知道"现在几点/在哪个目录",全靠 harness 注入。
  - **两套占位符机制**:
    - `$ARGUMENTS`(及 `$N`/`$name`/`${CLAUDE_SKILL_DIR}` 等)= harness 在**发给模型前程序化字符串替换**,确定性。
    - `$CURRENT_DATE` = **不是 Claude Code 内置 token**,原样保留为字面量;它"能用"是因为 harness 另行把当前日期注入了会话上下文,再靠**模型阅读理解**去锚定——非确定性。
  - **更稳的写法** `` !`date +%F` ``(动态上下文注入:发给模型前先跑 bash,把真实日期硬替进去)。但该语法是 **Claude Code 专属**,可能不跨平台 → 这是"**确定性 vs 可移植性**"权衡,正是 T4 要处理的矛盾。
  - **风险**:换个不注入日期的 harness/场景,`$CURRENT_DATE` 会**静默失效**且不报错(与 T2 issue #58 同类隐患)。
